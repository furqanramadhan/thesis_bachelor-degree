  1. Data BMKG

Badan Meteorologi, Klimatologi, dan Geofisika adalah sebuah lembaga pemerintah non-departemen di Indonesia yang bertugas mengamati, mengolah, menganalisis, dan menyebarluaskan informasi serta peringatan dini mengenai cuaca, iklim, kualitas udara, gempa bumi, dan tsunami di seluruh wilayah Indonesia. Setiap dataset memiliki status untuk menandai apakah dataset masih mentah, sudah dibersihkan, atau sudah tidak digunakan. Status lifecycle dijelaskan di bawah ini:

1. Raw

Status awal dari sebuah dataset. Dataset akan berada dalam status raw ketika:

  • Baru pertama kali diambil dari API (misalnya NASA POWER). Atau baru diunggah oleh pengguna secara manual.
  • Jika dataset sebelumnya sudah diproses lalu kemudian diperbarui (refresh) dari sumber aslinya maka statusnya kembali ke raw.

2. Latest

Dataset dari sumber API sudah diperbarui dan sesuai dengan data terbaru dari sumbernya.

  • Hanya digunakan untuk dataset yang berasal dari API, bukan dari unggahan pengguna.
  • Namun, jika dataset latest kemudian preprocessing, maka ketika dilakukan refresh ulang dari API, statusnya akan direset ke raw lagi.

3. Failed

Status ini bersifat sementara, tidak disimpan secara permanen di database.

Digunakan hanya untuk:

  • Menandai kegagalan saat pengambilan data dari API atau saat proses refresh.
  • Memberi respons error.

4. Preprocessed

Diberikan setelah proses pembersihan data berhasil dilakukan melalui sistem Flask.

Ciri-ciri:

  • Sistem akan membuat koleksi baru dengan diberi akhiran _cleaned.
  • Metadata asal tetap disimpan.
  • Hanya dataset dengan status raw atau latest bisa menjadi preprocessed.

5. Validated

Memiliki fungsi sama seperti preprocessed, yaitu menandakan bahwa data sudah siap digunakan untuk model atau analisis. Belum ada tahapan validasi terpisah, namun status ini disiapkan untuk pengembangan lebih lanjut. Validated dapat dianggap sebagai versi lain dari preprocessed.

6. Archived
Menandakan bahwa dataset:

  • Sudah tidak digunakan secara aktif.
  • Disimpan hanya untuk referensi historis.
  • Tidak akan diperbarui atau diproses lagi.

3. Integrasi sistem ke AWS-AI

Integrasi dilakukan dengan mendeploy backend aplikasi kedalam Amazon Web Services (AWS). Tujuannya adalah agar preprocessing dataset dan analisis otomatis dapat berjalan secara terpusat di cloud, tanpa perlu dijalankan manual di lokal. Pada tahap ini, server Flask yang berfungsi sebagai modul pembersihan data, validasi, dan peramalan dihubungkan dengan frontend berbasis Next.js melalui endpoint public AWS.

3.1 Setup Lingkungan AWS

Langkah pertama dilakukan dengan membuat instance Amazon EC2 bertipe t3.micro, kategori Free Tier keperluan komputasi ringan, proses API dan analisis data. Instance diberi nama flask-instance dan dijalankan pada region Asia Pacific (Sydney). Instance ini cocok untuk hosting Flask backend (otomasi preprocessing Python, analisis data, API Holt-Winters).

Instance bernama flask-instance sedang Running.

Instance type: t3.micro (masuk kategori free tier, cocok untuk deployment ringan Flask API).

Private IP: 172.31.24.17

Flask di-deploy menggunakan konfigurasi Ubuntu, dengan instalasi dependensi Python, Flask, dan library python pandas, numpy, serta statsmodels untuk perhitungan metode Holt-Winters. Server Flask dikonfigurasi agar dapat menerima permintaan dari frontend dan menjalankan fungsi preprocessing secara otomatis setiap kali dataset baru diunggah atau diperbarui seperti pada gambar 3.1.

Gambar 3.1 Tampilan Instance EC2 Berjalan di AWS Console

3.2 Integrasi Backend Flask dan Frontend Next.js

Backend Flask yang telah di-deploy di AWS EC2 kemudian dihubungkan dengan frontend Next.js melalui endpoint publik yang diberikan AWS, misalnya pada gambar 3.2.

Gambar 3.2 Contoh endpoint backend AWS Compute

Alamat ini digunakan oleh frontend untuk mengirim request API:

  • Menjalankan proses preprocessing otomatis (pembersihan missing value, normalisasi),
  • Menjalankan peramalan iklim dengan metode Holt-Winters,
  • Mengambil hasil statistik deskriptif untuk ditampilkan dalam tabel atau grafik.

Integrasi ini memungkinkan proses yang sebelumnya manual (misalnya upload dan pembersihan dataset di lokal) dapat dilakukan langsung melalui antarmuka web oleh admin. Ketika admin menekan tombol “Preprocess” atau “Run Forecast”, frontend akan memanggil endpoint Flask di AWS untuk menjalankan skrip pembersihan dan analisis secara otomatis.

Penelitian ini dimulai dengan pengumpulan data yang dilakukan oleh penulis dan tim dengan tujuan untuk memperoleh gambaran awal kondisi pertanian di Provinsi Aceh terkhusus di  beberapa kabupaten penghasil padi terbesar yaitu Aceh Besar, Aceh Jaya, Pidie, dan Aceh Utara. Di Aceh Besar, pengumpulan data difokuskan pada Kecamatan Indrapuri, Montasik, dan Darussalam; di Aceh Jaya pada Kecamatan Jaya, Setia Bakti, dan Teunom; di Pidie pada Kecamatan Pidie dan Indrajaya; serta di Aceh Utara pada Kecamatan Lhoksukon Pengumpulan data dilakukan melalui penyebaran kuesioner kepada para petani di wilayah tersebut. Dari hasil kuesioner diperoleh informasi yang cukup komprehensif mengenai praktik pertanian, meliputi jenis bibit yang umum digunakan, luas lahan yang dikelola, pola masa tanam dan panen, hingga estimasi modal yang dikeluarkan petani untuk setiap musim tanam.

Gambar Grafik perbandingan Jenis lahan di setiap Kabupaten

Dari data yang diperoleh, terlihat bahwa di Kabupaten Aceh Besar dan Aceh Jaya para petani umumnya sudah memanfaatkan sistem sawah irigasi. Sementara itu, di Kabupaten Pidie mayoritas petani masih menggunakan kombinasi antara irigasi dan tadah hujan. Berbeda halnya dengan Kabupaten Aceh Utara, di mana sebagian besar petani masih mengandalkan sawah tadah hujan. Meskipun terdapat perbedaan sistem pengelolaan air, terdapat kesamaan yang cukup menonjol, yaitu mayoritas petani mengaku pasokan air yang tersedia masih belum mencukupi, terlebih ketika lahan yang dikelola memiliki luas yang lebih besar. Data seperti ini sangat penting untuk menjadi dasar dalam penelitian dan perencanaan pengelolaan sumber daya air, sehingga dapat mendukung peningkatan produktivitas pertanian di wilayah tersebut.

Gambar Grafik Jadwal tanam di setiap Kabupaten

Data lain yang tidak kalah penting adalah pola tanam. Di wilayah yang umumnya melakukan dua kali tanam seperti Aceh Besar, Pidie, dan Aceh Utara, mayoritas petani menanam pada bulan Mei–Juli dan November–Januari, meskipun terdapat juga sebagian yang menanam pada Agustus–Oktober. Sementara itu, di Aceh Jaya sebagian besar petani hanya melakukan sekali tanam, umumnya pada periode Mei–Juli atau Agustus–Oktober. Dari data ini saja dapat terlihat adanya keterkaitan yang kuat antara pola tanam dengan musim hujan, yang berperan penting dalam menentukan keberhasilan produksi padi di setiap kabupaten.

Gambar Grafik Penggunaan Bibit Padi

Pemilihan bibit merupakan aspek penting bagi petani, karena bibit unggul umumnya memiliki umur panen sedang (90–110 hari) atau panjang (115–125 hari). Namun, pilihan ini tidak selalu sesuai dengan kondisi di lapangan, terutama pada wilayah dengan curah hujan terbatas, angin kencang, atau faktor lingkungan lainnya. Hal ini menyebabkan variasi dalam penggunaan bibit di tiap kabupaten. Di Aceh Besar dan Pidie, mayoritas petani cenderung memilih bibit berumur panjang, meskipun sebagian juga menggunakan bibit berumur sedang. Berbeda dengan Aceh Jaya, di mana penggunaan bibit relatif seimbang antara bibit berumur singkat dan sedang. Sementara itu, di Aceh Utara mayoritas petani lebih banyak mengandalkan bibit berumur panjang.  

1.2 IMPLEMENTASI

Berdasarkan gambaran umum pertanian di beberapa kabupaten di Aceh yang telah dipaparkan sebelumnya, terlihat bahwa ketersediaan air, pola tanam, serta pemilihan bibit menjadi faktor penting yang memengaruhi produktivitas petani. Informasi ini menjadi landasan dalam merancang sebuah sistem yang mampu membantu petani dan pengambil kebijakan dalam mengelola data iklim secara lebih efektif. Pada tahap implementasi, Sistem Manajemen dan Analisis Data Iklim dengan metode Holt-Winters dikembangkan menggunakan framework Next.js dan Flask serta didukung dengan database MongoDB. Sistem ini dirancang dengan dua jenis pengguna utama, yaitu admin dan petani.  

Gambar Flowchart Sistem

Untuk mudah memahami sistem dibuat flowchart sistem, dimana proses dimulai dengan pengambilan data otomatis dari beberapa sumber seperti BMKG, NOAA, NASA, dan citra satelit. Data yang diperoleh kemudian dibersihkan, disimpan ke dalam database, dan difilter sesuai kebutuhan. Sebagian data selanjutnya diramalkan menggunakan metode Holt’s Winter dan hasilnya ditampilkan pada halaman monitoring agar dapat diakses oleh petani.

  1. Dekomposisi Deret Waktu

Dekomposisi deret waktu dilakukan untuk memahami komponen-komponen yang ada dalam data dengan memisahkan data deret waktu menjadi tren, musiman, dan residual. Proses ini penting untuk mengidentifikasi pola yang ada sebelum melakukan pemodelan dengan metode Holt-Winters. Proses dekomposisi menghasilkan tiga komponen utama:

  • Komponen Trend merepresentasikan arah atau pola jangka panjang dalam data, yang mengindikasikan apakah data mengalami peningkatan, penurunan, atau tetap stabil seiring waktu. Komponen ini menunjukkan perubahan sistematis yang terjadi dalam jangka waktu yang relatif panjang.
  • Komponen Musiman Seasonal menampilkan pola berulang dan teratur dalam data yang terjadi pada interval waktu tertentu. Komponen ini mencerminkan fluktuasi periodik yang konsisten, seperti variasi musiman pada parameter meteorologi.
  • Komponen Residual merupakan variasi acak atau ketidakteraturan yang tersisa setelah menghilangkan komponen trend dan musiman. Analisis pola residual dapat membantu mengidentifikasi outlier, anomali data, atau komponen tidak teratur lainnya yang tidak dapat dijelaskan oleh trend dan pola musiman.

        

Gambar diatas Dekomposisi deret waktu curah hujan

Gambar diatas menunjukkan dekomposisi data curah hujan menjadi tiga komponen utama. Komponen trend memperlihatkan fluktuasi jangka panjang dengan fase penurunan dan peningkatan curah hujan pada periode berbeda, yang mencerminkan variabilitas iklim regional. Komponen seasonal menampilkan pola tahunan yang konsisten, dengan puncak pada musim hujan dan lembah pada musim kemarau. Sementara itu, komponen residual menunjukkan variasi acak di luar pola utama, termasuk beberapa anomali berupa curah hujan ekstrim yang tidak dapat dijelaskan oleh trend maupun siklus musiman.

Gambar Dekomposisi deret waktu kelembaban relatif

Gambar diatas menunjukkan dekomposisi data kelembaban relatif menjadi tiga komponen utama. Komponen trend memperlihatkan perubahan jangka panjang dengan kecenderungan menurun pada beberapa periode, kemudian meningkat kembali pada tahun-tahun terakhir, mencerminkan dinamika iklim yang mempengaruhi kelembaban udara. Komponen seasonal menampilkan pola tahunan yang konsisten, dengan fluktuasi berulang yang mengindikasikan adanya siklus musiman. Sementara itu, komponen residual menunjukkan variasi acak di sekitar pola utama, termasuk beberapa deviasi ekstrim yang merepresentasikan kondisi kelembapan anomali yang tidak dapat dijelaskan oleh trend maupun pola musiman.

Gambar Dekomposisi deret waktu suhu udara

Gambar diatas menunjukkan dekomposisi data deret waktu suhu udara. Komponen trend memperlihatkan kecenderungan peningkatan suhu udara secara bertahap, meskipun diselingi oleh periode penurunan pada beberapa rentang waktu, menggambarkan fluktuasi jangka panjang dalam suhu rata-rata. Komponen seasonal menampilkan pola musiman yang konsisten dan berulang setiap tahun, dengan puncak suhu pada musim tertentu dan penurunan pada musim lainnya, mengindikasikan dominasi faktor iklim musiman. Komponen residual menunjukkan variasi acak di luar pola trend dan seasonal. Variasi ini umumnya tersebar merata di sekitar nol, namun terdapat beberapa titik ekstrim yang menunjukkan anomali suhu pada periode tertentu.

  1. Perancangan Holt-Winters

Berdasarkan hasil dekomposisi, pola musiman bersifat konstan sehingga pera- malan model Holt-Winters additive pada semua variabel. Sebelum melakukan peramalan perlu dilakukan inisialisasi nilai awal untuk panjang periode seasonal. Inisialisasi untuk panjang periode ditentukan sebesar 365 dikarenakan data deret waktu harian.

Implementasi metode Holt-Winters dilakukan pada backend Flask menggunakan pustaka statsmodels (fungsi ExponentialSmoothing). Sistem ini secara adaptif menentukan nilai seasonal periods melalui kombinasi Autocorrelation Function (ACF), Fast Fourier Transform (FFT), dan seasonal decomposition. Model kemudian dilatih dengan grid search untuk memperoleh kombinasi terbaik dari alpha, beta, gamma, serta konfigurasi trend dan seasonal sesuai karakteristik variabel (NDVI, curah hujan, suhu, kelembaban).

Keakuratan ditingkatkan melalui validasi time series split, serta post-processing berbasis batasan domain agar hasil tetap relevan secara ilmiah. Selain itu, damped trend digunakan untuk menghindari overforecasting. Sistem ini fleksibel, men- dukung data harian (BMKG) maupun 16-harian (NDVI), serta menyesuaikan horizon peramalan sesuai kebutuhan analisis.

1.2.2 Deployment

Tahap implementasi berikutnya adalah proses deployment dari sistem yang telah dibangun. Bagian frontend sistem di-deploy menggunakan layanan Vercel, karena platform ini mendukung penuh framework Next.js yang digunakan dalam pengembangan serta menyediakan proses integrasi dan pembaruan otomatis dari repository Git. Dengan demikian, setiap perubahan kode pada frontend dapat langsung di-deploy tanpa konfigurasi yang kompleks.

Untuk penyimpanan data, sistem menggunakan layanan MongoDB Atlas sebagai cloud database. Pemilihan MongoDB Atlas dipertimbangkan karena saat ini data yang disimpan masih berupa teks dan relatif ringan, sehingga layanan ini sudah mencukupi kebutuhan sistem. Selain itu, MongoDB Atlas menyediakan skalabilitas yang fleksibel untuk pengembangan di masa depan.

Awalnya, sistem peramalan direncanakan untuk diimplementasikan pada platform Google Cloud Platform (GCP) dengan memanfaatkan layanan Google Compute Enginer (GCE). Namun, dalam pelaksanaannya dilakukan peralihan ke Amazon Web Services (AWS) dengan Elastic Compute Cloud (EC2). Perubahan ini dilakukan karena pendaftaran akun GCP terkendala metode pembayaran yang mewajibkan kartu kredit/debit berlogo Visa/Mastercard, sedangkan AWS lebih fleksibel melalui masa percobaan (free trial) tanpa verifikasi ketat. Selain itu, AWS memiliki dokumentasi yang komprehensif, komunitas yang luas, serta ekosistem layanan yang lengkap sehingga lebih sesuai untuk kebutuhan pengembangan dan potensi ekspansi sistem di masa depan.

Gambar arsitektur google compute engine

Sebagai layana         infrastruktur berbasis cloud, Google Compute Engine (GCE) memungkinkan pengguna menjalankan mesin virtual (VM) sesuai kebutuhan. GCE menyediakan dua tipe utama VM, yaitu predefined dengan konfigurasi standar serta custom yang dapat disesuaikan jumlah vCPU dan memori. Layanan ini mendukung berbagai jenis beban kerja melalui tiga keluarga mesin, yakni general purpose, compute optimized, dan memory optimized, sehingga dapat digunakan untuk aplikasi web, basis data, hingga komputasi berat.Dengan kombinasi ini, GCE dirancang agar aplikasi tetap andal, efisien, dan hemat biaya sesuai kebutuhan pengguna.

Gambar Infrastruktur AWS ec2 Instance

Di sisi lain, Amazon Web Services (AWS) menyediakan layanan serupa melalui Amazon Elastic Compute Cloud (EC2). EC2 memungkinkan pengguna membuat dan mengelola instance dengan konfigurasi yang fleksibel, baik dari sisi prosesor, memori, maupun penyimpanan. AWS memiliki ekosistem layanan yang lebih luas, seperti penyimpanan objek melalui S3, basis data melalui RDS, serta layanan pemantauan dengan CloudWatch, sehingga memudahkan integrasi jika kebutuhan sistem berkembang. Selain itu, AWS unggul dalam ketersediaan dokumentasi, komunitas yang besar, dan fleksibilitas pada masa percobaan (free tier) yang tidak terlalu ketat dalam verifikasi kartu pembayaran. Hal ini menjadikannya pilihan praktis untuk tahap pengembangan dan eksplorasi sistem.

Sementara itu, untuk variabel kelembapan udara relatif, diperoleh nilai RMSE sebesar 21.86 dan MAPE sebesar 27.27%, dengan performa terbaik pada skenario 80:20. Adapun untuk variabel suhu udara, model menunjukkan kinerja terbaik dengan RMSE sebesar 0.97 pada skenario 80:20. Nilai-nilai metrik tersebut mengindikasikan bahwa model memiliki kinerja prediksi yang cukup baik, terutama untuk data suhu udara yang stabil, sementara prediksi curah hujan dan kelembapan masih cukup sensitif terhadap proporsi data pelatihan. 33 Berikut ditampilkan hasil peramalan terhadap curah hujan, suhu udara, dan kelembapan udara relatif pada data BMKG untuk 365 hari mendatang, menggunakan model Holt-Winters dengan pembagian data 90:10, yang merupakan konfigurasi terbaik.

1.3.1 Pembahasan

Berdasarkan hasil implementasi dan pengujian yang dilakukan, beberapa hal dapat dibahas sebagai berikut:

  1. Sistem manajemen data telah berfungsi dengan baik dalam mengorganisasi dan menampilkan informasi. Data yang tersimpan dapat diakses dengan mudah, sehingga mendukung pengelolaan informasi secara lebih terstruktur.
  2. Fleksibilitas pengolahan data terbukti melalui kemampuan sistem untuk memilih koleksi dan kolom tertentu. Fitur ini memberikan ruang bagi pengembangan lebih lanjut, misalnya penerapan pada dataset lain di luar penelitian ini.
  3. Fitur visualisasi mendukung pemahaman hasil secara lebih komprehensif. Sistem tidak hanya menyajikan angka, tetapi juga menampilkan grafik serta informasi error, sehingga administrator memperoleh gambaran yang lebih jelas secara visual.
  4. Model peramalan Holt-Winters menunjukkan kinerja yang baik pada data suhu dan kelembaban, dengan tingkat akurasi yang cukup tinggi. Namun, hasil pada data curah hujan kurang optimal, sehingga pemanfaatannya untuk kalender tanam masih terbatas. Meskipun demikian, model ini berpotensi dimanfaatkan untuk tugas lain, seperti pemantauan tren iklim jangka pendek atau evaluasi data lingkungan perkotaan.
  5. Peralihan dari GCP ke AWS Instance EC2 juga berhasil dengan baik, dokumentasi dan dukungan komunitas sangat membantu mempercepat proses peralihan dan membuat sistem berjalan dengan baik di server AWS yang baru.
  6. Potensi pengembangan sistem masih terbuka, antara lain dengan memperbaiki metode peramalan curah hujan, menambah dukungan terhadap model lain untuk perbandingan, serta meningkatkan interaktivitas dashboard agar lebih mudah digunakan oleh administrator maupun pengguna non-teknis.

        

Meski demikian terdapat beberapa catatan untuk pengembanagn lebih lanjut :

  1. Sistem fetch data masih belum tersedia, sehingga admin harus mengunggah data secara manual dan menjalankan peramalan secara terpisah.
  2. Metode Holt-Winters bersifat sederhana dan kurang cocok untuk peramalan jangka panjang yang lebih detail, sehingga perlu dipertimbangkan penggunaan model yang lebih canggih.
  3. Ruang lingkup sistem saat ini terbatas pada Kabupaten Aceh Besar, padahal berpotensi diperluas dengan cakupan wilayah dan data yang lebih beragam.

KESIMPULAN DAN SARAN

2.1 KESIMPULAN

Berdasarkan hasil penelitian, implementasi sistem, dan pengujian yang telah dilakukan, dapat disimpulkan beberapa hal sebagai berikut:

  1. Sistem manajemen data telah berjalan dengan baik, mencakup fitur penting seperti kalender tanam, sistem unggah dan pengelolaan dataset, sistem peramalan data, manajemen bibit, serta manajemen pengguna. Hasil pengujian fungsional menunjukkan bahwa seluruh fitur utama dapat berfungsi sesuai spesifikasi yang direncanakan.
  2. Pengujian model menunjukkan bahwa tingkat akurasi terbaik diperoleh pada konfigurasi pembagian data 90:10 untuk variabel curah hujan dan suhu udara, sedangkan variabel kelembapan udara relatif mencapai performa terbaik pada skenario 80:20. Model Holt-Winters menghasilkan nilai RMSE sebesar 12.97 (curah hujan), 21.86 dengan MAPE 27.27% (kelembapan udara), dan 0.97 (suhu udara), yang mengindikasikan kinerja cukup baik, khususnya pada data suhu udara yang lebih stabil.
  3. Secara umum, metode Holt-Winters mampu menangkap pola musiman dan tren jangka pendek dengan konsisten, sehingga berguna untuk melihat gambaran umum iklim. Namun, model masih kesulitan menangani nilai ekstrem sehingga detail prediksi, khususnya pada curah hujan dan kelembapan, belum optimal.

2.2 SARAN

  1. Mengingat Holt-Winters berbasis exponential smoothing yang cenderung merata-rata data, disarankan untuk menambahkan model lain yang lebih canggih agar dapat menangani nilai ekstrim dengan lebih baik serta meningkatkan akurasi peramalan.
  2. Perluasan cakupan data dari berbagai wilayah lain sangat penting agar sistem tidak hanya terbatas pada Kabupaten Aceh Besar, melainkan dapat dimanfaatkan secara lebih luas.
  3. Pengembangan selanjutnya dapat difokuskan pada otomasi fetching data dari sumber resmi, sehingga admin tidak lagi perlu mengunggah data secara manual, sekaligus memungkinkan sistem peramalan berjalan secara otomatis dan real-time.
